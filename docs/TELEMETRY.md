# evo-agent 遥测透明度声明

> **适用版本**：evo-agent 0.2.0（2026-10-13 复核；初版分析基于 0.1.0，2026-09-26）
> **政策来源**：evorule 生态遥测透明度四原则（见 §一），2026-09-26 裁定
> **承诺**：本文档随软件网络行为变化在同一版本内更新；文档头部始终标注当前分析的版本与日期。

---

## 一、evorule 生态遥测政策总纲

evorule 生态所有软件（含 evo-agent）遵守以下四条原则：

1. **自身软件绝无遥测**。evorule 生态自研软件不包含任何形式的遥测：不上报使用统计、不上报崩溃报告、不采集设备指纹、不做用户行为跟踪、不嵌入任何统计 SDK。
2. **依赖选择原则：原则上不使用具有遥测功能的软件**。选型引入任何第三方依赖（crate/npm 包）时，将「是否存在遥测功能」作为评估项；已知含遥测的软件原则上不引入；功能相当且无遥测的替代品优先。
3. **诚实边界**。我们**不保证**引入/依赖的第三方软件绝对不存在遥测功能。第三方软件是黑盒加供应链问题：其传递依赖、发布渠道、未来版本都可能在我们掌控之外发生变化。对此我们不做出超出能力的保证，只承诺尽力审计并公开结论与方法（见 §四）。
4. **审计承诺**。evorule 依据自身能力与理解，对生态软件进行遥测分析：检索代码与依赖清单、盘点全部网络出口、区分「功能必需外发」与「遥测外发」，并将结论以本文档形式公开。分析有局限，方法可复核——我们鼓励并指导使用者自行验证（§四）。

**「遥测」的定义**（本文口径）：软件在**未经使用者发起**的情况下，将使用行为、设备信息、错误报告、环境数据等发送给软件作者或第三方的行为。须区分两类行为：

- **遥测**：软件自发向外发送数据——本文承诺零存在；
- **功能外发**：使用者主动使用某个需要联网的功能（如 LLM 对话）时产生的数据传输——本文如实告知内容与去向，并给出控制手段（§三）。

## 二、本软件遥测机制分析

### 2.1 结论摘要

**evo-agent 不包含任何遥测。** 全部源码与依赖清单经检索核查：无统计 SDK、无崩溃上报、无使用数据收集。软件联网行为仅限以下三类，均由功能或使用者的显式配置驱动：

| 网络出口 | 去向 | 性质 |
|---|---|---|
| evorule 工作区 API | `config.evorule.base_url`（默认 `http://localhost:8080`，使用者自配） | 产品功能：治理规则执行与工作区协作 |
| LLM 供应商 API | 使用者配置的供应商（见 2.3） | 产品功能：对话与审批所需 |
| agent 的 `http_get` 工具 | 该工具调用时的目标 URL | agent 功能：**每次调用需人工审批** |

### 2.2 遥测痕迹检索（方法与结果）

对仓库全部源码（Rust `src/`、前端 `web/src/`、构建配置）做关键词检索：`telemetry / analytics / sentry / posthog / mixpanel / amplitude / beacon / crash_report / track_event` —— 零命中（子串匹配存在大小写误报可能，如标识符含 `sEntry`，逐条人工复核后排除）。

依赖清单核查（Cargo.toml 与 web/package.json）：

- **Rust 侧**：tokio、axum、reqwest、serde、serde_json、regex、jsonschema、blake3、tracing、tracing-subscriber、prometheus、rustyline、clap、toml、subtle、rand、chrono、bytes、url、similar、async-stream、futures-core、futures-util、tokio-util、async-trait、thiserror、tower、tower-http、http、rusqlite、ignore、globset、grep-matcher、grep-regex、grep-searcher、notify、notify-debouncer-full、git2，以及 evorule-constitution、evorule-bundle、evorule-hash（自研生态件）——全部为功能库，**无任何统计/遥测 crate**。上述各库在本分析时点均不知晓包含遥测功能。
- **前端侧**：运行时依赖仅 monaco-editor（编辑器组件，无遥测）；开发依赖 svelte、vite、vitest 及插件（构建与测试工具，不随构建产物分发，均无遥测）。

### 2.3 网络出口逐一分析

**① evorule 工作区 API**（`src/api/api_core.rs`、`src/api/evorule_client.rs`、`src/api/workspace_client.rs`）
请求目标由配置项 `config.evorule.base_url` 决定，默认指向本机 `http://localhost:8080`。用途：加载治理规则集、上报治理事件（审批记录、审计留痕）到使用者自己的 evorule 工作区。**数据留在使用者控制的服务上**，不经由任何 evorule 官方服务器中转。

**② LLM 供应商 API**（`src/io_handlers/llm_handler.rs`、`src/agent/audited_llm.rs`）
这是唯一的内容外发：agent 会话消息、工具调用的必要上下文、审批请求的说明内容会发送给**使用者配置的 LLM 供应商**。供应商为 MiniMax / DeepSeek / OpenAI 三选一（均走 OpenAI 兼容协议）；**未配置任何供应商时，LLM 功能不可用，软件其余功能（编辑器/文件/搜索/治理）完全可用且零外发**。注意：未做任何配置时默认供应商指向 MiniMax（`https://api.minimaxi.com`）——若希望启用 LLM 功能并指定供应商，请在配置或环境变量中显式设置。

**③ `http_get` 工具**（`src/builtin_tools/http_get.rs`）
agent 抓取网页的通用工具，目标 URL 由 agent 依据任务决定，但**每一次调用都会先弹出审批请求，未经批准不发生任何请求**。审批事件留痕于本地审计流。

**④ `/metrics` 本地端点**（`src/api/metrics.rs`、`src/api/agent_api.rs`）
本机 serve 暴露 Prometheus 文本格式指标端点（调用次数、耗时分布等运行指标）。**定性：被动暴露，不是遥测**——数据只等待使用者自己的监控系统来抓取，evo-agent 自身不向任何外部地址推送指标。若不需要，可用防火墙规则或反向代理屏蔽该路径。

### 2.4 本地数据面（不外发，如实列出）

- **日志**（`tracing`）：写入本地文件/控制台，不上传。
- **审计留痕**：治理事件（审批、工具调用）存于本地及使用者的 evorule 工作区（① 的目标）。
- **工作台状态**（标签页/设置等）：存于浏览器 localStorage。

## 三、功能必需的数据外发与控制手段

| 数据 | 去向 | 控制手段 |
|---|---|---|
| 会话消息与上下文 | 使用者配置的 LLM 供应商 | 换供应商/本地部署兼容端点（如 Ollama）；不配置则不发生 |
| agent 拟抓取的 URL | 目标网站 | 每次调用人工审批（拒绝即无请求） |
| 治理事件与审计数据 | 使用者的 evorule 工作区 | 自托管，数据自主 |
| 运行指标 | 本机 `/metrics` 端点 | 不抓取即不离开本机 |

产品路线中规划中的治理增强（尚未发布）：AI 补全/Inline Chat 的逐文件排除清单（`.evoignore`，发送前过滤）、数据外发类操作的强制人工审批红线。本文档将随这些功能发布同步更新。

## 四、诚实边界、方法局限与自行验证

**本分析的能力边界，如实告知：**

1. **传递依赖未逐一人工审读**。我们审计了直接依赖清单并核查其是否知晓含遥测，但 Rust/npm 生态的依赖树庞大，未对每一个传递依赖做源码级审读。缓解：构建产物可复查（§四 自行验证方法）。
2. **第三方软件未来版本可能变化**。某依赖今天无遥测，不代表其新版本不引入。缓解：对依赖采用版本钉制，升级前复核；并按 §五 承诺处置。
3. **构建与分发渠道不在审计范围**。包管理器（crates.io/npm）的投递过程、镜像源、下载缓存的安全性超出本文档范围。
4. **分析基于版本快照**。结论对应文档头部标注的版本源码快照；后续版本见头部更新记录。

**自行验证方法（不依赖我们的结论）：**

- **网络行为实测**：用抓包工具（Wireshark、Fiddler、系统防火墙日志）观察 evo-agent 进程的全部出站连接——预期仅出现使用者配置的 evorule 工作区地址与 LLM 供应商地址，此外不应有任何外联。发现未知外联即违反本文档承诺。
- **源码复核**：仓库公开，按 2.2 的关键词清单自行检索；依赖清单见 Cargo.toml 与 web/package.json，可逐项核查。
- **离线运行**：不配置 LLM 供应商、不使用 `http_get` 审批放行时，软件可在完全断网状态下正常提供编辑器/文件/搜索/治理功能——断网实测是最直接的证明。

## 五、变更与承诺

1. **新依赖遥测检查义务**：引入任何新依赖前，评估其遥测状况；发现遥测功能即回归「无替代不引入」——有替代选替代，无替代则评估禁用其遥测的可行性，二者皆不可行则放弃引入。
2. **发现问题的处置承诺**：任一版本中发现依赖携带遥测行为且已进入产品，我们将：公告受影响版本 → 依 1 的顺序处置 → 发布修复版本 → 在本文档记录事件与处置。
3. **文档随动**：软件网络行为发生任何变化（新增出口、新增依赖类别），本文档在同一版本内更新。文档头部始终标注当前分析的版本与日期。
