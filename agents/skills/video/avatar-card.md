# 数字人主持卡

## 定位（何时用）

M3 avatar-spokesperson 线 avatar_prep 段：数字人形象选型、音色匹配、口型驱动质量判断、样片确认。本卡管**数字人呈现判断**；脚本归上游通用卡，外部 API 依赖面（avatar 生成腿）的可行性判断归 producer 卡。

## 前置依赖（声明化引用）

- 引擎 CLI：`engine.py plan <project_dir>`（预演）、`engine.py build <project_dir>`（装配）、`engine.py verify <project_dir>`（交叉核对）
- 阶段链：brief→script→shot_plan→avatar_prep→edit→assembly→delivery
- 技能：`video-narration`（配音文本与样音闸——数字人音源同源）、`video-producer`（外部 API 可行性与成本）、`video-taste`（形象气质与受众锚定）
- 谓词面：qc_anatomy 口型子集（嘴部帧间连续性）——驱动质量机器初筛引谓词名

## 作业流程

1. 形象配置定型：形象（性别/年龄感/着装/场景）从需求 brief 推导并按 taste 卡受众旋钮校准——形象与受众错位（面向青年的产品配暮气形象）即回调，不进生成。
2. 音色同源锁定：数字人音源与配音腿同源（narration 卡样音闸过的音色）——音色与口型驱动必须同一音轨，双源硬拼必炸口型。
3. 驱动质量三查：①口型开合与音节对位（qc_anatomy 口型子集初筛）②表情与语义匹配（陈述内容配陈述脸，不出现语义-表情错位）③头部微动自然度（僵硬定格/过度摇晃两极都不过）。
4. 样片确认闸：正式合成前先出 10~20s 样片（含口型/表情/转场各一）交上游确认——形象与音色一经确认锁定，中途换形象=重开机成本归上游裁。
5. 不自然谷排查：数字人「恐怖谷」敏感面（眼神/微表情）在样片段专项排查——上游观感反馈「瘆得慌」类模糊意见时，逐项列可疑清单供上游指认。
6. 外部 API 依赖留痕：avatar 生成腿的 API 版本/参数/耗时写台账（外部依赖变化影响复现，如实记录不掩盖）。

## 质量判据

- 机器可查：qc_anatomy 口型子集过；样片确认记录在案；台账 API 参数面齐全。
- 人工判断：形象-受众匹配有结论；表情-语义匹配抽验；恐怖谷排查清单过。

## 闸提示（何时停待人审）

- 样片确认闸（强制，任何数字人项目必停）；形象中途变更（成本重估）；上游对观感的模糊不满（需结构化指认）。

## 边界（不做何事+降级路径）

- 不替上游选形象美学倾向（列候选+适配分析，选择归上游）；不跳样片闸直接全片合成；API 限速/配额问题不上报解决之前不重试轰炸。
- avatar 生成腿不可用时降级路径：退守「画外音+图文」方案（脚本与配音件复用），标注「无数字人版」，交 producer 卡裁是否接受。
