# 视频旁白表演卡

## 定位（何时用）

项目需要旁白或配音轨时在岗：解说词定稿、配音 provider 选型确认、样音验收。纯字幕无配音项目不启用本卡。本卡管**旁白文本与表演要求**；配音生成由 provider 腿执行，音频工程归引擎装配段。

## 前置依赖（声明化引用）

- 引擎参考面：`engine.py timeline`（时间轴——旁白时长与镜头对位）、`engine.py build`（字幕与音频装配）
- 产物契约：build/subs.srt / build/subs.ass（字幕双格式）
- 技能：`video-producer`（provider 降级路由判断）、`video-taste`（语气旋钮约束解说词风格）

## 作业流程

1. 时长对位先行：读 timeline 确认每镜头时长，解说词按镜头对位写作——每句长度匹配镜头时长（中文约 4-5 字/秒），超时先削词再谈加速。
2. 风格约束承接：按品味卡三旋钮的语气项写作——克制的项目解说词短句少形容词，热情的项目允许情绪词；语气与锚定注冲突时回品味卡裁决。
3. 信息密度检查：每个镜头段只承载一个主信息点；两句说不清的内容拆镜头或砍信息，不写长流水句硬塞。
4. 配音 provider 对接：确认项目配置的 TTS provider 可用性与音色样音——任何 provider 首次使用必须过样音确认闸（一段 10-20s 样本交上游听），不拿全片配音赌音色。
5. 字幕与配音一致性：解说词定稿后字幕从同一文本源生成（不手工双维护）；配音与字幕文本有出入即红牌，回查生成链。
6. 段落时长复核：配音回来后逐段对照 timeline——超时段落回第 1 步削词重录，不靠引擎硬压时长。

## 质量判据

- 机器可查：build 后 subs.srt 条数与镜头 cues 对齐；音频轨时长与 final.mp4 一致（verify rc=0）。
- 人工判断：样音过闸记录；解说词语气与品味锚定一致；每镜头段单信息点。

## 闸提示（何时停待人审）

- 样音确认闸（任何 provider 首次使用/换音色）；解说词定稿（上游确认后进配音）；配音回检发现超时段落需削词重录时。

## 边界（不做何事+降级路径）

- 不直接改引擎产出的音频装配（意见归本卡，施工归引擎）；不跳过样音闸直接全片配音；不用「差不多得了」替代逐段时长复核。
- TTS provider 全部不可用时降级路径：退守纯字幕方案（subs 双格式照常产出），显式标注「无配音版」，交 producer 卡判断是否接受或外接。
